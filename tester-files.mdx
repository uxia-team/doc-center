Some tasks can't be completed without something to upload. If your flow asks participants to attach a CV to a job application, upload an ID for verification, import a CSV, or add a profile picture, AI participants need a real file to hand over.

That's what **files** are for. You import them once into a Task block, and AI participants use them whenever the flow reaches an upload step.

## Add files

<Steps>
  <Step title="Open the Files modal">
    On a live website or Figma prototype task, click **+ Add files** under the URL.
  </Step>
  <Step title="Import your files">
    Drag and drop files into the modal, or click to browse. Remove a file with its **X** button.
  </Step>
  <Step title="Close the modal">
    Click **Done**. The button on the block now shows how many files you added, such as **2 files added**.
  </Step>
</Steps>

## What you can upload

Import any file the flow might ask for. Common cases:

| Use case | Typical file |
|---|---|
| Job application | A CV or cover letter in PDF |
| Identity or verification step | A scanned document or photo |
| Data import | A CSV or spreadsheet |
| Profile setup | An avatar or profile image |
| Media upload | A short video or audio clip |

### Supported formats and limits

<CardGroup cols={2}>
  <Card title="Formats" icon="file">
    **Any file type**, except:

    - Executables
    - Scripts
    - Active web files, such as HTML or SVG
    - Macro-enabled documents
  </Card>

  <Card title="Limits" icon="gauge">
    **Up to 100 MB** per file

    **Up to 5 files** per Task block
  </Card>
</CardGroup>

Those exclusions exist because the file is handed to a real browser during the session. Anything that could run code is blocked, for your protection and ours.

<Tip>
  If the flow has more than one upload step, import a file for each. Give them names that describe what they are, such as `cv.pdf` or `id-document.png`. AI participants see the file names, so clear names help them pick the right file at each step.
</Tip>

## How Uxia handles your files

A file can carry far more personal data than a form field, so it's handled with the same care as [credentials](/tester-credentials).

### Encrypted in transit and at rest

Files travel over TLS and are stored encrypted at rest. They stay attached to the Task block you imported them into, so you can re-run the test without uploading them again. They're retrieved only when a session reaches an upload step.

### Never read by the AI model

AI participants see only each file's name and type, never its contents. When the flow reaches an upload input, the file is attached directly, the same way a person picks it from a file picker. As a result, nothing inside your file can leak into transcripts or insights.

<Note>
  This also means participants can't act on what a file contains. If your task depends on knowing something, such as a name, a date, or a reference number, put it in the [task](/mission) or in a [credential](/tester-credentials), not inside the file.
</Note>

### Never used for training

Nothing you submit to Uxia is used to train or fine-tune any model, for Uxia or for any third party. Files are excluded by design, since their contents never reach a model in the first place.

### Scoped to your workspace

Files belong to the test they were imported into, inside your workspace. Only you and the teammates you've invited to that workspace can access them: never other organizations, and never other Uxia customers.

If you remove someone from the workspace, they lose access to the test and its files with it.

<Warning>
  Treat workspace membership as the access boundary. Anyone who can open a test can access the files attached to it, so only invite teammates who should have that level of access.
</Warning>

## Best practices

The safest file is one that wouldn't matter if someone else saw it.

<Steps>
  <Step title="Use fake documents, not real ones">
    A CV for a made-up candidate works just as well as a real one for testing an upload flow. Never upload a real applicant's CV, a real customer's contract, or your own ID.
  </Step>
  <Step title="Strip personal data before uploading">
    If you must start from a real document, replace names, emails, phone numbers, addresses, and ID numbers with test values first.
  </Step>
  <Step title="Keep files small and simple">
    The limit is 100 MB, but a one-page PDF uploads faster and fails less often than a large scan. Participants only need the upload to succeed, not the document to be realistic.
  </Step>
  <Step title="Match the format the flow expects">
    If the form only accepts PDF, importing a DOCX makes the flow fail at the upload step, and that failure shows up in your results as a usability issue that isn't one.
  </Step>
  <Step title="Remove files you no longer need">
    Files stay attached to the Task block until you remove them. Clear out anything you're done with.
  </Step>
</Steps>

<Warning>
  Avoid uploading anything covered by a confidentiality agreement, or any document that contains real personal data of a third party. Use a synthetic equivalent instead.
</Warning>
