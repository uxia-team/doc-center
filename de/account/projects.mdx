In Uxia ist ein Projekt eine Möglichkeit, Ihre Forschungsarbeit rund um eine bestimmte Initiative, einen Kunden, einen Produktbereich, eine Kampagne oder eine User Journey zu organisieren.

Je mehr Tests ein Team durchführt, desto wichtiger wird es, die Forschung geordnet und leicht auffindbar zu halten. Ein Projekt dient als Ordner in Ihrem Workspace, in dem Sie zusammengehörige Tests gruppieren können. So vermeiden Teams, dass alle Tests an einem Ort durcheinanderliegen, und können Forschung im Lauf der Zeit leichter finden, vergleichen und wieder aufgreifen.

## Mit Projekten Tests rund um die tatsächliche Arbeit organisieren

Ein Projekt kann für alles stehen, woran Ihr Team arbeitet. Sie könnten zum Beispiel ein Projekt anlegen für:

- Ein neues Feature oder einen neuen Ablauf
- Ein Kundenprojekt
- Einen Sprint
- Einen bestimmten Markt, eine Zielgruppe oder einen Geschäftsbereich

In jedem Projekt können Sie die Tests hinzufügen, die zu dieser Initiative gehören. Das gibt Ihrem Team eine übersichtlichere Struktur und macht leichter erkennbar, welche Tests mit demselben Forschungsziel zusammenhängen.

## Projekte erstellen und verwalten

- **Ein Projekt erstellen.** Öffnen Sie **Projects** in der Seitenleiste und klicken Sie auf **Create project**.
- **Einen Test zu einem Projekt hinzufügen.** Öffnen Sie auf einer Testkarte das Menü und wählen Sie **Move to**. Wählen Sie ein Projekt oder **Create new project**.
- **Umbenennen, archivieren oder löschen.** Verwenden Sie das Menü auf einer Projektkarte. Wenn Sie ein Projekt archivieren, werden auch alle darin enthaltenen Tests archiviert; Sie können die Archivierung später wieder aufheben. Sie können nur Projekte löschen, die keine Tests enthalten.
- **Projekte finden.** Wechseln Sie zwischen den Tabs **Active** und **Archived** und sortieren Sie nach Name, Erstellungsdatum oder Änderungsdatum.

## Beispiel

Angenommen, Ihr Team gestaltet das Onboarding einer Banking-App neu. Sie könnten ein Projekt namens **New Onboarding Flow** anlegen.

In diesem Projekt könnten Sie Folgendes aufbewahren:

- Einen ersten Test am Prototyp, der einen Aufgabenblock, einen Umfrageblock zu Erwartungen und Verständnis sowie einen Block zur Barrierefreiheitsprüfung für die wichtigsten Screens kombiniert
- Einen zweiten Test nach Designänderungen, um die Ergebnisse zu vergleichen
- Einen Test auf der Live-Website, sobald der neue Ablauf veröffentlicht ist

Alle diese Tests gehören zur selben Initiative. Wenn Sie sie in einem Projekt bündeln, lässt sich die Forschung leichter verwalten und auswerten.
