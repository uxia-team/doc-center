title: "Stop Condition"
description: "Define the on-screen end state that ends a live website or Figma prototype task, so every run finishes cleanly."
---

The **Stop condition** defines exactly when a run ends: the moment participants know the goal has been reached. It applies to live website and Figma prototype tasks, where it's required. A participant navigating a real, open-ended website or prototype needs a clear signal for when to stop, rather than wandering indefinitely.

The stop condition takes up to 500 characters. A [media prototype task](/media-canvas) has no stop condition: the run ends when participants reach the final frame you set on the canvas.

## Writing a stop condition

State the end state in plain language, tied to something observable on screen. For example:

> "Stop once you reach the order confirmation page."

> "Stop when the new account has been created and you land on the dashboard."

> "Stop when card information is requested."

A good stop condition pairs naturally with a good [task](/mission): the task says what to accomplish, and the stop condition says how you'll know it's done. Anchoring it to a specific page, confirmation message, or state change keeps runs clean and comparable across participants.

- **Describe one end state.** Avoid alternatives joined with "or", which make it unclear when the run is over.
- **Keep it on screen.** Avoid conditions participants can't see, such as "and a confirmation email arrives".
- **Stop before steps you don't want completed.** If participants shouldn't submit a form or place a real order, end the run at the review or payment screen. See [AI participant restrictions](/account/security/ai-participant-restrictions).

<Tip>
  If participants stop too early or run long, tighten the stop condition before anything else.
</Tip>

The stop condition also has a **Tips** button that suggests rewrites. See [Refine it with Tips](/mission#refine-it-with-tips). As in the task, think-aloud or feedback instructions here trigger a warning and are removed before the test runs.
